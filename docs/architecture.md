# 架构设计

当前已实现独立视频制作服务、生成服务适配器、后台 worker、DSH 工具和预览路由；B 站发布仍为后续模块。

## 分工

- DSH 助手：理解用户要求、写文案、选择素材、调用工具。
- dsh-bili-publisher：校验账号和发布参数、预览、上传、提交、记录结果、查询状态。
- dsh-bili-whale（可选）：提供养鱼人设、看视频、日记和作息，通过 DSH 工具调用发布能力。

发布插件独立打包、安装、升级。普通发布能力不依赖养鱼插件的私有实现。

## 模块

- DSH 集成：插件生命周期与模型工具注册。
- 发布服务：草稿、参数校验、提交记录及状态转换。
- 凭据提供器：独立配置；可选读取已有养鱼插件的登录态。
- B 站适配器：动态接口、稿件查询、平台错误处理。
- 视频上传适配器：文件上传与投稿实现，可固定依赖版本替换。

## 调用流程

```text
用户要求
  → 助手准备文案和素材
  → 发布工具校验参数、展示预览
  → 根据明确的发布要求执行提交
  → 保存平台返回的内容 ID
  → 回读结果并返回链接、审核状态
```

只要求写草稿时停留在内容准备阶段。用户明确要求发布具体内容时可进入提交阶段。

## 状态和一致性

草稿、文件摘要、目标账号、提交状态和平台 ID 保存在运行目录。上传或提交结果不确定时，应先查询核实；核实前保留防重复记录。

并发提交、文件变化、账号切换和网络超时是首版需要验证的关键场景。视频上传完成、投稿被接受、审核通过应分别展示。

## 凭据

模型只接收账号身份和校验结果。Cookie 等凭据由服务模块读取并用于与 B 站通信，错误输出和预览应隐藏凭据。

插件支持指定凭据来源。与养鱼插件组合时采用可选适配器，账号和凭据路径由本机配置决定。

## 当前制作模块

`storyboard.js` 校验分镜；`providers.js` 调用生图与配音接口；`render.js` 负责素材准备、按句配音及 FFmpeg 合成；`service.js` 与 `store.js` 管理草稿和后台任务；`index.js` 注册 DSH 工具；`routes.js` 提供受 DSH 认证保护的预览。CLI 与插件调用相同服务层。
