# 部署流程

当前版本是初始化骨架，尚未具备实际发布能力，也尚未在服务器安装。

## 目标流程

1. 在本地修改源码，运行相关检查。
2. 提交代码并推送 GitHub。
3. 服务器克隆仓库；更新时拉取已验证的 commit 或 tag。
4. 安装该版本依赖。
5. 使用 DSH 的目录插件安装方式挂载包。
6. 重启 DSH，核对插件加载及工具注册。
7. 在服务器配置运行目录和账号，验证登录与预览。
8. 使用用户明确授权的内容进行实际发布验证。

## 开发阶段的目录安装示意

现有 DSH 插件采用以下命令形式，具体 profile 和路径按目标 DSH 实例填写：

```sh
dsh plugin --profile <profile> add "link:/path/to/dsh-bili-publisher"
```

初始化骨架可用于检查包结构，发布工具将在后续版本中实现。安装步骤需要随目标 DSH 版本完成实际验证。

## 更新与回退

正式部署使用可追溯的 commit 或 tag。更新前记录正在运行的版本；需要回退时切回上一已验证版本、安装对应依赖并重启 DSH。

GitHub 用于同步源码。账号凭据、媒体、草稿和发布历史保存在服务器运行目录中。
